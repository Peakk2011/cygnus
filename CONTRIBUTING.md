# Contributing to Cygnus

## What Your Code Needs

It must:
- Work with no errors (main-process & cygnus-usage)
- Be tested and ready to use
- Follow our design and style
- Handle errors the right way
- Be complete (no half-finished work)

Don't send code that's broken, still being worked on, or hasn't been tested.

## How to Send Your Code

1. Create a branch for your work
2. Make your changes using our style and design
3. Test it - make sure it builds and runs
4. Send a pull request that shows:
   - What you did
   - How it works
   - That it's ready to use

## What I Check

- Does it work?
- Does it follow our design? (API Design: '@using' '@name' etc.)
- Does it handle errors right?
- Is the code clean?
- Can people actually use it?

If it doesn't pass these checks, I'll reject it.

## Rules

- Keep your code like the rest of the project
- Check all data that comes in
- Handle all error cases
- Use the same naming style (camel case)
- Add notes if the code is complex (add 'docs/' folder and write notes in there)

## Have a Question?

Look at the existing code and docs (README.md) first.
